# Causality — 因果推演规则

本文件是 Phase 05（Causal Propagation）的完整操作规则。Skill 的可信度取决于因果链的质量。

---

## 1. 六问框架（必答，非可选）

每个重大分叉**必须**回答，任何一问缺失则该步推演不合格：

1. **What changed?** 发生了什么变化？
2. **Why?** 为什么会发生？（因果解释，不是相关性描述）
3. **Immediate effect?** 直接后果（1 年内）？
4. **Secondary effect?** 二阶后果（社交圈、生活方式、自我认知的变化）？
5. **Long-term effect?** 长期影响（3–5 年+）？
6. **Uncertainty?** 这一步的推断有多可靠？

执行规则：
- 六问中 What 和 Why **必须显式出现在输出里**（各至少一行），不得只在"心里回答"后直接写结论。
- 其余四问如果某一步不适用（例如某步只有直接后果、无长期影响），可以合并写，但必须显式说明"此步无长期影响/不确定性为……"。
- 如果任何一问无法回答，说明这一步的推演不可靠。选择：
  - 降低确定性标注（从 `[推断]` 降为 `[可能]` 或 `[假设]`）
  - 或者放弃这条推演线，告诉用户"这一步我推不出合理依据"

---

## 2. 单变量原则（详细规则）

### 2.1 分叉瞬间

在分叉点上，除了用户指定的那个决策改变，以下全部保持不变：

- 性格与心理状态
- 家庭与经济背景
- 健康状况
- 时代背景与外部环境
- 已有的人际关系
- 技能与能力

### 2.2 什么可以变

只有因果链导致的后续变化。每一步变化必须能追溯到上一步。

### 2.3 什么不能变（无论因果链多长）

- 用户的本质性格（除非长期经历产生了合理的性格变化，且标注）
- 用户的家庭关系的基本性质（除非因果链导致关系变化）
- 外部世界的客观事实（某个公司仍然存在/不存在，某个人仍然在那个时间点做那件事）

### 2.4 违规判定示例

```text
违规：2020 去上海 → 2022 成为部门主管 → 2025 创业成功 → 2030 CEO
问题：中间没有任何因果链，每一步都是跳跃。

合规：2020 去上海 → [推断] 进入更大平台，节奏更快
      → [可能] 收入提升但生活成本也高
      → [可能] 接触到不同行业的人，视野变化
      → [假设] 某个时刻出现转行/创业机会
      → [推断] 做出选择，进入新路径
      → [可能] 后续路径走向 [……]
```

## 3. 因果现实性检查（每 3–5 年强制执行）

**检查的不是"结果是否太极端"，而是因果链是否成立。** 真实的人生可能出现极端结果——极端不是问题，无法解释才是问题。**CLE 不因反事实结果"过于成功""过于失败"或偏离一般人群分布而自动回拉。"接近普通人群分布"不是硬约束。**

每 3–5 年检查以下维度：

| 检查项 | 合格标准 |
| --- | --- |
| 因果成立 | 每一步变化都有"为什么"，且能追溯到上一步 |
| 不依赖巧合 | 没有把过多好事堆在一条路径上（连续升职+贵人+暴富=违规） |
| 不违反现实约束 | 收入/职级/健康没有超出该年限该行业该城市的合理范围**除非因果链能解释** |
| 人格一致 | 没有为了让剧情走下去而假设用户变成了另一个人 |
| 无未模拟的重大事件 | 没有突然引入"某公司倒闭""某次意外"等用户未提及且未推演的事件 |

**强制拦截规则**：
- 任一检查项不合格 → 必须在输出中显式写"修正为……"并说明修正原因。
- 连续两个时间分段都出现不合格 → 停止该条推演线，如实告诉用户"这条路径的因果链撑不住"，从头或从断裂点重推。**（停止的原因只能是因果链断裂/巧合依赖/现实约束冲突等，绝不能是"结果太极端"。）**
- 不合格的原因如果是"需要引入巧合/运气" → 按因果链断裂处理（§4）。

---

## 4. 因果链断裂

以下情况说明因果链断裂，必须停止或降级：

- 无法解释"为什么"
- 需要引入巧合/运气才能继续
- 需要假设用户具有不同的性格才能继续（违反单变量原则）
- 推演结果依赖某个未验证的重大外部事件

处理方式：告诉用户"这一步我没有足够的依据继续推下去"。宁可留白，不可编造。

---

## 5. 输出纪律

- 因果链用结构化格式输出（见 workflow.md Phase 05 模板）。
- 每个重大变化至少显式写出 What + Why 两行，其余四问可合并但不得省略。
- 推演完成后向用户确认："这是这条路的因果骨架。有什么地方你觉得不合理或者不符合你对自己的了解吗？"（可与下一阶段的引入合并，不必单独等确认。）
- 用户指出不合理时：修正，标注修正原因，重新推演后续。
